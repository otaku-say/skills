# tini —— 迷你 init：转发信号 + 收割僵尸子进程

容器/PID 1 场景的极简 init。iSH 上的用途是：给**守候型脚本**转发信号、收割自己产生的僵尸子进程。
它**不是**通用的命令包装器——只是跑一条命令又不需要信号转发/收尸时，别套它，白多一层进程。

本份二进制含 **iSH 适配补丁**（见文末），已真机验证。

## 推荐用法

```sh
# 1) 守候脚本的标准写法（iSH 上 -s 会降级告警但仍可用）
timeout 60 tini -s -- sh demo.sh < /dev/null

# 2) 退出码透传：子进程退出码原样变成 tini 的退出码
tini -- sh -c 'exit 5'; echo $?          # 5

# 3) 信号转发：TERM 进来 → 转给子进程 → 自己以 128+15=143 退出
timeout 20 sh -c 'tini -- sleep 30 & p=$!; sleep 1; kill -TERM $p; wait $p; echo $?'   # 143

# 4) 子进程又自己开了子进程时，把信号发给整个进程组
tini -g -- sh -c 'sleep 30 & sleep 30 & wait'

# 5) 把某个人尽皆知的退出码归一成 0（注意语义：是"重映射"，不是"透传"）
tini -e 143 -- sh -c 'exit 143'; echo $?   # 0

# 6) 版本 / 帮助
tini --version        # tini version 0.19.0
tini -h
```

## 常用参数（v0.19.0）

| 参数 | 作用 |
|---|---|
| `--version` | 打印版本后退出 |
| `-h` | 打印帮助 |
| `-s` | 注册为 subreaper（要求 Linux ≥ 3.4；**iSH 不支持，会警告后继续**） |
| `-g` | 信号发给子进程所在的**整个进程组** |
| `-p SIGNAL` | 父进程死亡时给自己发该信号（如 `-p SIGKILL`） |
| `-e CODE` | 把退出码 CODE（0–255）**重映射为 0** |
| `-v` | 更详细的日志，最多重复 3 次 |
| `-w` | 收割进程时打印警告 |

环境变量：`TINI_SUBREAPER` / `TINI_VERBOSITY` / `TINI_KILL_PROCESS_GROUP`（与对应参数等价）。

## 退出码 / 错误处理

- 默认**原样透传**子进程退出码（这是它比 `&` 后台跑更可靠的原因）。
- 自己被信号打死：`128 + 信号号` → `TERM=143`、`INT=130`。
- `-e N` 把退出码 N 改写成 0（用于"这个码不算失败"的白名单）。

## iSH 注意事项

- 本份二进制含 **iSH 信号修复补丁**：上游用 block+`sigtimedwait` 等信号，在 iSH 上 **pending 信号永不投递**（表现为 TERM 收不到、不转发、进程杀不掉、一直挂死）→ 补丁改为 handler 置标志 + 主循环 100ms tick 轮询转发（Linux 行为等价）。
- `-s` 在 iSH 上**注册不了真 subreaper**（无 `PR_SET_CHILD_SUBREAPER`）：tini 会打印警告然后照常运行。语义边界要记住：**自己的孩子照常收割，"被托孤的孙子进程"收割做不到**。
- iSH 不支持高编号实时信号（上限 63），补丁里跳过。
- 真机实测：`TERM → 143` ✓、`INT → 130` ✓、`tini -s -- sh demo.sh < /dev/null` → `rc=0` ✓。
- 单独一条命令不建议套 tini；需要"信号转发 / 收尸 / 进程组"时才用。
